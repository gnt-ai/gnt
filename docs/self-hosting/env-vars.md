# Env var reference

Looking for the short version — which of these you actually need before
you can do anything useful? See "What's actually required" in
[`README.md`](./README.md). It's three keys (Anthropic, Groq, ZeroEntropy);
`setup.sh` at the repo root asks for all three and generates everything
else on this page for you. Everything below is the full reference for when
you need it — connecting a specific integration, debugging a boot failure,
or auditing what a self-hosted deploy actually requires.

Two tables. `apps/api`'s is generated straight from the `Settings` model
(`apps/api/src/gnt/config.py`) by `gen_env_vars.py` in this directory — run
`python3 docs/self-hosting/gen_env_vars.py` after touching `config.py` to
regenerate it, so this table can't quietly drift from the real source of
truth the way a hand-typed one would. `apps/store`'s is hand-enumerated
(it's a plain TypeScript `process.env.X` read, not a pydantic model) but
audited against the actual reads in `apps/store/src/http/server.ts`,
`apps/store/src/native/embed.ts`, and `apps/store/src/native/rerank.ts` —
not against `.env.example`, which is missing at least one real var (see the
note under that table).

A field marked "Required: yes" with no default makes `Settings()` raise at
import time if it's unset — the api container won't start, full stop, not a
degraded mode. A field with a default still might functionally be required
for whatever feature reads it (e.g. `slack_client_id` has no pydantic
default and is required to boot even if you never connect Slack — see the
"connector fields are boot-required" note below the table).

**Every one of these is required to boot, not just to use the feature.**
`slack_client_id/secret/signing_secret/state_secret/token_encryption_key`,
`github_pat_encryption_key`, `zendesk_token_encryption_key`,
`notion_client_id/secret/state_secret/token_encryption_key`,
`linear_client_id/state_secret/token_encryption_key`, and
`intercom_token_encryption_key` are all plain `str` fields with no
`| None` and no default in `config.py` — `Settings()` fails to construct
without a value for every one of them, even if you never connect that
integration. `apps/api/.env.example`'s own comment says as much
("Connector credentials you don't plan to use... still need *some*
non-empty string"). Fill every one with a throwaway placeholder unless
you're actually wiring up that connector.

**`GROQ_API_KEY` is required too and isn't mentioned in the root README's
"what you bring" list** — it backs server-side voice-input transcription
(`transcribe_model`, `whisper-large-v3-turbo`) and has no default in
`config.py`. The api container won't boot without it even if you never use
voice input. Get a free-tier key at console.groq.com, or set any non-empty
placeholder string — nothing calls it unless a request actually hits
`/v1/transcribe`.

**The Fernet-format keys are not interchangeable with `openssl rand -hex
32`.** `slack_token_encryption_key`, `github_pat_encryption_key`,
`zendesk_token_encryption_key`, `intercom_token_encryption_key`,
`notion_token_encryption_key`, and `linear_token_encryption_key` all get
handed to `cryptography.fernet.Fernet(...)`, which requires a 32-byte
urlsafe-base64 key, not an arbitrary hex string. Generate them with:

```bash
python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Everything else (`contributor_hash_secret`, `slack_state_secret`,
`notion_state_secret`, `linear_state_secret`, `store_internal_api_secret`,
`approval_signing_secret`) is a plain shared secret, not a Fernet key —
`openssl rand -hex 32` is correct for those.

**`store_internal_api_secret` and `approval_signing_secret` must byte-for-
byte match `GNT_STORE_INTERNAL_API_SECRET` and `GNT_APPROVAL_SIGNING_SECRET`
in apps/store's own env** (see the table below) — mismatched values fail
closed (every call between the two services rejected), not open.

## apps/store

Hand-enumerated from the actual `process.env.X` reads in
`apps/store/src/http/server.ts`, `apps/store/src/native/embed.ts`, and
`apps/store/src/native/rerank.ts` — not from `.env.example`.

| Env var | Required | Default | Notes |
|---|---|---|---|
| `GNT_STORE_PORT` | no | `8787` | Internal API port. `docker-compose.yml` doesn't publish it to the host — only `api`/`worker` reach it, over the compose network. |
| `GNT_STORE_BIND` | no | `127.0.0.1` | `docker-compose.yml` overrides this to `0.0.0.0` so `api` can reach it across containers. |
| `GNT_STORE_INTERNAL_API_SECRET` | **yes** | — | Server refuses to start without it (`server.ts` throws at startup, not lazily). Must match `STORE_INTERNAL_API_SECRET` in apps/api's env. |
| `DATABASE_URL` | **yes** | — | NativeStore is Postgres-only, no in-memory mode. Plain `postgres://` form, not apps/api's `postgresql+asyncpg://` form. `docker-compose.yml` sets this to the same Postgres the api container uses. |
| `STORE_BACKEND` | no | `native` | `native` is the only supported value — gnt's own storage/retrieval, no third-party knowledge-store dependency. Any other value refuses to start with a clear error rather than misbehaving silently. |
| `GNT_STORE_CLONES_DIR` | no | a tmpdir | Where org rules repos get cloned to disk. Set to a persistent volume path in production so clones survive a restart instead of re-cloning; `docker-compose.yml` doesn't set this, so clones live in the container's ephemeral filesystem. |
| `GNT_APPROVAL_SIGNING_SECRET` | effectively yes | — | Must match `APPROVAL_SIGNING_SECRET` in apps/api's env. Not checked at startup the way `GNT_STORE_INTERNAL_API_SECRET` is, but every approved-status write fails without it. |
| `ZEROENTROPY_API_KEY` | **yes, for real search** | — | Read directly by `native/embed.ts` and `native/rerank.ts` (`zeroEntropyEmbed`/`zeroEntropyRerank`) — embeddings and reranking for rule search under `STORE_BACKEND=native`, which is what `docker-compose.yml` sets. The store process boots fine without it (nothing reads it at startup), but any call that actually embeds or reranks a rule throws `EmbedError` at request time. Get a key at zeroentropy.dev. |
| `GNT_STORE_ALLOW_PUBLIC_DOMAIN` | only if publicly exposed | unset | `server.ts` refuses to start if `RAILWAY_PUBLIC_DOMAIN`/`RAILWAY_TCP_PROXY_DOMAIN` is set and this isn't `1` — a guardrail against accidentally exposing this internal-only service to the internet. Doesn't apply to the compose setup (nothing here sets a public domain), only relevant on Railway or an equivalent PaaS. |
| `GNT_STORE_TEST_FAKE_EMBED` | no | unset | Test/eval-only deterministic fake embedding. Never set this in a real deployment. |

Two Railway-specific vars (`RAILWAY_PUBLIC_DOMAIN`, `RAILWAY_TCP_PROXY_DOMAIN`)
and two eval-fixture-only vars (`GNT_STORE_EVAL_EMBEDDINGS_FIXTURE`,
`GNT_STORE_EVAL_RERANK_FIXTURE`/`_RECORD`) are read by the source but have
no place in a self-hosted deploy — omitted above, not missed.
